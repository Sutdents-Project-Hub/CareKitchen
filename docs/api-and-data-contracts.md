# API and Conversation Data Contracts

## Routes

| Method | Route | Behavior |
|---|---|---|
| GET | `/api/chat` | Returns `{ mode }`, where mode is `openai`, `local`, or `unavailable`. |
| POST | `/api/chat` | Validates the user turn and conditions; returns updated conditions and meal cards. |

POST accepts `{ persona, text, context, previousMealIds?, language? }`. `persona` is `elder`, `caregiver`, or `family`. `language` is optional: `"en"` requests English output; omission preserves the existing Traditional Chinese behavior for older callers. Types are in `web/lib/contracts.ts`; request validation is in `web/lib/server/turn.ts`.

Messages are limited to 600 characters and requests to 24 KiB. `MealContext` carries servings, meals, budget, inventory, known package prices, confirmed exclusions, equipment, time, preferences, unresolved restrictions, and inventory-only mode. Empty values mean that servings, budget, time, or quantity are unknown. Inventory and package prices can be compared only in matching units (`g`, `ml`, `個`, `份`). A package quote includes ingredient, package quantity, unit, and total package price.

Successful responses include `mode`, `message`, `context`, `cards`, `responseType`, and `unknowns`; `modelInfo` is present when the model produced output. The server recalculates costs. Cost status is `within`, `unknown`, or `no_budget`; candidates known to exceed budget are not returned. Errors use `{ message }`: 400 invalid input, 403 origin restriction, 413 oversized request, 415 unsupported format, 429 rate limit, and 503 upstream unavailable. Responses use `Cache-Control: no-store`.

## Session and sharing

Messages and conditions live in React state for the current browser tab. The server validates each turn and does not expose a private conversation-history query. Users can preview and manually copy shopping text derived from meal cards.

Persistent public conversation snapshots are not implemented. Before adding them, define preview, de-identification, consent, expiration, and owner withdrawal. Storage provider, retention, cost, and public access remain undecided; see [data and storage](data-and-storage.md) and [security and privacy](security-and-privacy.md).

## Model output and evidence

Model decisions may return `clarification` with a field and supporting phrase. The server checks evidence, asks fixed questions for unresolved conditions, and blocks unresolved ingredient exclusions. `cards[].reason` is generated by application code for eligible meals. `mode` describes configured service mode; only `modelInfo` indicates model output for that turn. The read-only `/evidence/waicy` route reads recorded synthetic cases only.

## English V6 conversation behavior

English V6 uses existing request and response shapes. A why follow-up reads `previousMealIds` in display order, reruns eligibility, and returns explanations and only the still-eligible cards. A swap excludes those IDs from that turn. Local clarifications and explanations can reply without `modelInfo` even in OpenAI mode.
