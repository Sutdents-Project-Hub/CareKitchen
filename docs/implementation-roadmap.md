# CareKitchen｜實作順序、工作拆解與階段驗收

> 路線圖保留原有階段與驗收關卡。現行本機實作涵蓋框架、三角色、條件編輯、多輪規劃、規則檢查、餐點卡、採買預覽及 OpenAI 介接程式。
>
> OpenAI 真實呼叫、正式模型逐版比較、真人可用性、公開部署、最終對話證據及正式交件仍待完成。詳見 [Web README](../web/README.md) 與 [實驗計畫](evaluation-and-iteration.md)。
> 主目標：WAICY 2026 第 4 賽道交件，重視服務明確性 25 分與迭代改善 25 分，而不是最大功能數。

## 0. 交給實作 Agent 前的基本原則

- 先讀 `AGENTS.md`、`README.md`、`docs/product-spec.md`、`docs/architecture.md`、`docs/agent-design.md`、`docs/evaluation-and-iteration.md`、`docs/competition.md`。
- 只建立單一 `web/` Next.js full-stack；執行官方 bootstrap 產生可執行骨架，**不要把新專案建在 web 的下一層**。
- 實作行為要以可觀察驗收為單位，先一條 end-to-end 主流程，再擴充。
- 每階段留下 prompt 版本、commit、人工測試與失敗證據，避免最後只剩展示截圖。
- 需動用模型 API／付費服務、雲端資料庫、公開部署或 GitHub push 時，先依當次授權與外部配置確認；不因規劃文件自動獲授權。

## 2. Agent 任務拆解（建議逐個 PR／checkpoint）

### TASK-01：官方框架 skeleton

- 在 `web/` 根執行 Next.js 官方 initializer，TypeScript、App Router、pnpm；確認 Node 24 LTS、框架版本是否當前相容。
- 建立最少 scripts、ESLint／TypeScript、品質檢查；不得自行假造 script 成功。
- 實作初期沒有連線資訊就用安全的 `.env.example`（不提交真實值）。
- Done：`web/package.json` 和 lockfile 直接存在、`pnpm lint`／`typecheck`／`build` 等**實際存在的指令**通過並留下輸出。

### TASK-02：角色入口與同一條聊天流程

- 建置首頁三角色、四個快捷意圖、對話輸入框、條件摘要。
- 先測手機及鍵盤路徑；當尚未接真實 AI 時顯示「示範 UI」而非假成功。
- Done：A/B/C 能帶著不同角色上下文進聊天；沒有姓名／病史必填欄位。

### TASK-03：真正 LLM 串接

- 經核准提供者／模型後建立 server-only SDK adapter；設定 timeout、quota、rate limit、重試上限、LLM schema 解析。
- 讓`POST /api/chat`取得真實生成回覆；記錄 prompt 版號／模型資訊供證據使用。
- Done：三角色各一次 API 互動有實際原始輸出、模型錯誤能有明確失敗畫面。

### TASK-04：條件與預算的確定性執行

- 建立 `MealContext` schema；狀態更新／合併；排除食材與設備檢查；價格必有來源／數量單位。
- 每個建議在展示前執行 server-side validator，計算已知新增採買費用與「超支／未確認／按已知價格未超支」。
- Done：`AC-02`、`AC-03`、`AC-05`、`AC-06`、`AC-07`、`AC-09` 通過實際測試。

### TASK-05：可交付餐點卡與摘要

- UI 顯示候選、待買、價格可信度、已確認條件和易讀步驟。
- 家屬摘要只由使用者確認後複製，拒絕無提示自動公開。
- Done：三種角色各完成一次完整情境而且同一組硬限制都有保留。

### TASK-06：真實 Baseline 與 Prompt 迭代

- 固定 30 題或實際合理數量，先儲存 Baseline，再做 V1/V2/V3 的真實測試；保留模型設定與全部原始輸出。
- 統計錯誤和改進；即使模型變差也完整揭露。
- Done：能從一個實際失敗案例追溯版本、變更、重跑及分數。

### TASK-07：公開 Demo 與只讀證據

- 先在無痕視窗驗證公開網址；資料保存、分享與刪除確認後才接持久化。
- 建立最終版至少 10 輪**真實**對話；透過匿名唯讀連結分享，無法實作站內分享時採合法可公開的完整原始對話文件，且需符合官方可存取要求。
- Done：非開發者可連線使用、能看到真正互動、對話證據連結可開啟且敏感資訊已移除。

### TASK-08：正式英文 PDF

- 引用實測數據、PDF 內兩種連結、三角色同題比較、失敗→改進、倫理限制及原創貢獻。
- 不把系統設計稿、預想數值或 AI 自動生成樣本說成已完成實驗。
- Done：用交件檢查表逐項勾選後送件。

## 4. Definition of Done（每個任務都要檢查）

- [ ] 實作與 `docs/product-spec.md` 的 AC 對齊，沒有自行新增醫療能力
- [ ] 新功能含「正常／價格未知／條件衝突／API 故障」必要情境
- [ ] 測試有實際輸出，未通過問題已標示
- [ ] 沒有 AI key、個資、學生資料或真實 .env 進 Git
- [ ] 有改 API／state／prompt／UI／部署時同步相關 README、`docs/`、`AGENTS.md`（必要時）
- [ ] 變更過任何架構、付費服務或使用者資料政策都已取得適當核准
- [ ] 對外文字沒有宣稱不存在的評審連結、測試分數或專業背書

## 5. 不建議的做法

不要優先做漂亮後台、會員登入、完整日曆、一週菜單、精準營養計算、藥品辨識、多模型 Agent 團隊、App 原生包、無謂向量資料庫、即時菜價爬蟲、複雜微服務。對這次第 4 賽道而言，能以真實證據改善特定使用者的多輪顧問體驗，比技術堆疊重要。
