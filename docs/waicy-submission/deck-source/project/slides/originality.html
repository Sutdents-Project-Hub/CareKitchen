09 · ORIGINALITY AND OUR CONTRIBUTION

What is new in this project

Confirmed versus unsure restrictions

Only restrictions the user confirms become hard filters. Vague ones stay pending, and the model can never lift them.

Package-level price honesty

Code prices whole packages, never prorated shares, and separates known subtotals from missing prices.

One state, three roles

The same conditions become a choice list, a condition checklist or a shopping summary, without weakening safety.

Proposal / verification split

The model decides and ranks; code verifies every card before the user sees it.

Evidence-first iteration

Failures are kept, not hidden: raw runs, prompt hashes and an unexplained error are all on file.
