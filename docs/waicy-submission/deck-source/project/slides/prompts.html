05 · ITERATIVE DESIGN · ADVISOR AND PROMPT DESIGN

Five versions, one model, one change at a time

VersionDesignWhat it was meant to fix
BaselineOne line: “Answer the user in Traditional Chinese.” Plain chat history, free text.Reference point: the same model with no CareKitchen design.
V1Model classifies and ranks candidates from the turn text and conditions. It may ask for any unknown.First end-to-end meal advisor.
V2Server-parsed conditions are trusted. Clarification must be structured, name the new missing field and quote the user.Needless re-asking, lost spoken edits, missing price intake.
V3Budget wording is separated from a shopping request. Reasons and screens depend on the role.All three roles got the same shopping summary.
V4Colloquial edits are parsed by the server. The model is reminded of pending exclusions and budget changes.“No eggs”, “keep it under 70”, “no fire today”, “now two of us”.

Same settings in every run: gpt-6-luna, reasoning effort none, store false. Baseline output limit 650 tokens; CareKitchen limit 250 tokens with structured output. Each run file records the prompt’s SHA-256 hash and the source snapshot. V2 and V3 prompt files were reconstructed from known differences and V4, not archived at the time. Prompt texts are in docs/evidence/prompts/.
